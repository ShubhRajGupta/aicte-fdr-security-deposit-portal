# Final pre-submission checklist

## 1. Rules and template
- [ ] Correct SIH edition/track and current official editable PPTX
- [ ] Original template preserved untouched; output edited from a copy
- [ ] Original slide count/order, page size, master, theme, fixed shapes, logo, title areas and footer preserved
- [ ] All new elements entirely inside approved body areas; reserved bands unchanged
- [ ] Institution/College SPOC rules checked separately
- [ ] File type, size, naming, deadline, video/demo and portal requirements verified

## 2. Identity and naming
- [ ] Official PS ID/title/theme/category copied correctly for metadata only
- [ ] Team name exactly `Phra Uma Thewi`; current Team ID verified
- [ ] Project name is a relevant Hindi/Sanskrit-origin word + full technical English expansion
- [ ] Old sample identifiers, `Contrast`, `TARANG` and percentages removed unless independently valid for this current project

## 3. Approach and content
- [ ] Slides 2–5 do not retell the PS; they demonstrate approach, research, architecture, maturity, field-fit, feasibility and impact
- [ ] Writing uses concise fragments/keypoints; no long prose blocks
- [ ] Important stages/modules/risks/metrics numbered where useful
- [ ] Every slide internally partitioned; large content areas used efficiently
- [ ] Technical visual explains a real workflow, architecture, method or evidence
- [ ] Each technology has a reason; no buzzword stack
- [ ] Current state vs proposed build vs future deployment is clear

## 4. Ground reality and claims
- [ ] Actual people/workflows/constraints are represented accurately
- [ ] No fabricated interviews, photos, user counts, tests, metrics or outcomes
- [ ] Field evidence has consent/appropriate anonymization; limitations are clear
- [ ] Prototype maturity label matches evidence
- [ ] Every number has units, baseline/context, status and source or explicit target label
- [ ] Failure cases, privacy/security, access, maintenance and adoption are considered where relevant

## 5. Typography and visuals
- [ ] Editable text uses Arial; H1/H2/body/caption hierarchy is obvious
- [ ] No emoji glyphs
- [ ] Selective bold, underline, highlight and accent colors only; template palette preserved
- [ ] Diagrams have readable labels, arrow directions and needed legends
- [ ] Real images/screenshots have appropriate source/licence/permission; illustrative imagery is not misrepresented as field evidence
- [ ] Text readable from projection distance; no words split or clipped
- [ ] No blank half-slide; no filler/decoration; visual density remains legible

## 6. Sources and QA
- [ ] Numeric reference marker on every slide including title metadata
- [ ] Every marker maps to a full, real reference on slide 6
- [ ] Source metadata/DOI/URL and visual licences checked
- [ ] `validate_deck.py` passed or all warnings resolved
- [ ] `compare_template_integrity.py` confirms original geometry/layout retained
- [ ] Deck exported to PDF/images and every slide visually inspected
- [ ] Final PPTX opens and required PDF (if any) has correct page count
- [ ] Team can defend each claim and likely judge questions
